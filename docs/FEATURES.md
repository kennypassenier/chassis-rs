# Features — chassis-rs

Phase 2 output. Ratings were taken by Kenny on 2026-09-05 in the
starterskit session (28-item form plus deep-dive round); this document
assigns the permanent IDs and the concrete test bar per feature. The
freeze is ratified in round **R2** (docs/PENDING_MINI_ROUNDS.md). After
the freeze, changes go through mini-rounds only.

Scale: **Essential** (kit 1.0, before the first existing project
migrates) · **Desired** (a 1.x release after the Essential list is
empty) · **Later** (registered, no hook in the kit) · **Don't do**
(dropped with Kenny's reason).

Every feature names its **test bar** now, so Phase 7 audits against a
sentence written before the code existed. "E2E" means a test that drives
the real binary or the real axum router over HTTP; "unit" means the pure
function.

## Round 1 — Kenny's features (K)

| ID | Rating | Feature | Test bar |
|---|---|---|---|
| K1 | Essential | **axum as the one web layer.** Health, metrics, API and dashboard all mount on one axum 0.8 router the kit builds; the project merges its own router into it. | E2E: a project router merged under `/v1` answers next to `/healthz` in one process. |
| K2 | Essential | **Configuration layering and control commands.** Precedence CLI flag > env var > config file > default; prefix derived from the app name (`INBOX_LISTEN`); `${VAR}` references in the file resolve from env; one state root (`<PREFIX>_STATE_DIR`) and every path derived from it, no per-path overrides; `--version`, `--check` and `--print-config` exit without opening a socket or reading secrets they do not need; `--print-config` shows every effective value with its source and secrets as `***`. | Unit: precedence table (4 sources × 3 knobs). E2E: `--print-config` output contains `source=env` for an overridden knob and never a secret's value; `--version` succeeds with no config and no state dir. |
| K3 | Essential | **Errors with a remedy, one JSON error shape, a Secret type.** The kit's error type requires a `remedy` string at compile time; every API error renders `{"error": …, "remedy": …}` with the mapped status; `Secret<T>` prints `***` in Debug and Display and exposes its value only through one named method. | Unit: constructing an error without a remedy does not compile (trybuild or a doc-test that must fail). E2E: an unauthorised request returns the JSON shape. Plaintext-scan test: no secret value in any log line or response body of the suite. |
| K4 | Essential | **Logging with tracing.** `tracing` + `EnvFilter` from `<PREFIX>_LOG` (default `info`), text to stderr, JSON when `<PREFIX>_LOG_FORMAT=json`. Payloads and secrets never reach a log line. | E2E: a request produces exactly one access line at `info`; the JSON mode parses as one JSON object per line. |
| K5 | Essential | **Graceful shutdown (norm N1).** SIGTERM or Ctrl-C: stop accepting, finish in-flight requests, run the project's flush hook, bounded by `<PREFIX>_SHUTDOWN_TIMEOUT_MS` (default 10000, refuses 0 or a non-number), exit 0 always, a second signal changes nothing. | E2E against the real binary: start, hold a slow request open, send SIGTERM, assert the request completes and exit code is 0; send two SIGTERMs, assert one clean exit. |
| K6 | Essential | **`/healthz` with version and subsystems.** Open JSON: `{"status": "ok"|"degraded", "version": "<cargo version>", "subsystems": {...}}`; a project registers subsystem checks; degraded returns 503 only when a check says so. No `/readyz`. | E2E: the `version` field equals `CARGO_PKG_VERSION`; a registered failing check flips status and code. |
| K7 | Essential | **`/metrics` with a kit baseline and a project registry.** Prometheus text: `<prefix>_build_info`, `<prefix>_uptime_seconds`, `<prefix>_http_requests_total{route,status}`; the project registers its own counters and gauges in the same registry; existing metric names of migrating projects can be kept verbatim; every metric carries a `blind_spot` note in the docs. `--healthcheck [url]` probes the process's own `/healthz` without curl. | E2E: scrape parses with a Prometheus text parser; counters never decrease across ten requests; `--healthcheck` exits 0 against a running instance and 1 against a closed port. |
| K8 | Essential | **Token login with sessions, two secrets.** Bootstrap token (`<PREFIX>_TOKEN`, ≥16 chars) compared constant-time; session cookie `<name>_session` HttpOnly, SameSite=Lax, optional remember-me (30 days); sessions persist in the encrypted store across restarts; wrong token → 200 with an inline error (never 401 to a browser); `<PREFIX>_SECRET_KEY` (32 bytes hex) encrypts the client store; one secret set without the other is a startup error whose message contains a freshly generated valid value; **no** unprotected mode: a dashboard without both secrets refuses to start (W6 = Don't do). | E2E: login flow with cookie, restart, cookie still valid; rotating `<PREFIX>_TOKEN` keeps client tokens working; missing one secret → exit 1 with a 64-hex candidate in the message. |
| K9 | Essential | **Passkeys behind Traefik.** WebAuthn registration and login (`webauthn-rs`), offered only when the request arrived over HTTPS (proxy header or TLS-terminating proxy); first passkey registered after a token login; credentials stored in the encrypted store. TLS is never terminated in-process (W8 = Don't do). | E2E with a software authenticator (webauthn-rs test tools): register + assert; over plain HTTP the passkey routes answer 404 and the login page hides the button. |
| K10 | Essential | **Guards with knobs.** Same-origin CSRF guard on state-changing requests (Origin vs Host, kyu's rule); rate limiting on `/login` and per client token on the API (`<PREFIX>_RATE_LIMIT_*`); body size and in-flight concurrency limits configurable (`<PREFIX>_MAX_BODY_BYTES`, `<PREFIX>_MAX_IN_FLIGHT`), 413 / 503 + Retry-After when exceeded. | E2E: cross-origin POST → 403; N+1 login attempts → 429; body over the cap → 413; shipped defaults pass their own validation (HTTPSwitchboard rule). |
| K10 (amendment 2026-09-06, CF-7) | — | **The CSRF rule reads `Sec-Fetch-Site` first** (`same-origin`/`none` pass, `cross-site`/`same-site` refused), `Origin` vs `Host` only without it; the security headers carry `referrer-policy: same-origin`, not `no-referrer`. Found live on CT 112: under `no-referrer` a browser form submit sends `Origin: null`, and the Origin-only rule refused every dashboard form from Chrome, login included. Refusals to a browser navigation render in the layout (`error.html`) instead of a bare JSON tab. | unit `csrf_passes_a_same_origin_browser_form_post_and_refuses_cross_site`, `navigations_get_errors_as_pages_and_scripts_get_json`; E2E `tests/browser_forms.rs` sends exactly Chrome's headers: login form accepted, cross-site refused as a page, script refused as JSON. Drill: one login + one form action in Chrome on CT 118 before every dashboard-touching kit release (TEST_PLAN §5). |
| K11 | Essential | **Listen address is a knob.** `--listen` / `<PREFIX>_LISTEN` / `listen =`; documented default `0.0.0.0:8080`; the bound address is logged at startup and shown by `--print-config`; tests always ask for port 0. | E2E: start on `127.0.0.1:0`, read the port from the log line, connect. Grep-test: no literal port in the suite except 0. |
| K12 | Essential | **Clients model, store trait, three buttons.** A client = name + token (32 random bytes, hex); actions issue, re-issue, revoke (row kept, name freed), delete; tokens encrypted at rest (XChaCha20-Poly1305 under `<PREFIX>_SECRET_KEY`), compared constant-time; `ClientStore` trait with the kit's encrypted-file implementation as default; page and URL are `/clients`, label overridable; row buttons: reveal for `<PREFIX>_REVEAL_SECONDS` (default 10), copy token only, copy full curl command; destructive buttons arm-before-act; busy state on slow buttons (rule 31). | E2E: full lifecycle over HTTP; plaintext-scan: the token appears in no page HTML except the reveal endpoint's response; a revoked token is refused within the same second; a second `ClientStore` (in-memory) passes the same suite (rule 7g). |
| K13 | Essential | **Last requests per client, last used.** The kit keeps the last N (`<PREFIX>_CAPTURE_KEEP`, default 20) requests per client token: method, path, redacted headers (Authorization, Cookie, anything matching a redaction list), body truncated at `<PREFIX>_CAPTURE_BODY_BYTES`, kept for `<PREFIX>_CAPTURE_TTL_SECS` (default 3600); shown expandable on the client's row; per token `last_used_at` and a request counter. Replaces Almanac's captures page and capture-only token. | E2E: three requests with a token → three rows, Authorization shows `***`, a body above `<PREFIX>_CAPTURE_BODY_BYTES` shows the truncation notice (bodies above `<PREFIX>_MAX_BODY_BYTES` are refused with 413 before capture — amended 2026-09-05, H15: the earlier "2 MB body" could never pass the 1 MiB default cap); after TTL the rows are gone; `last_used_at` moves (rule 22: shown to take two values). |
| K14 | Essential | **Send a test request.** A button per client row sends one request with that client's token to a project-declared test route with a project-declared sample body, so the request appears in K13 immediately. Never leaves the process. | E2E: click → a K13 row exists with `source=test`; a project without a declared test route shows no button. |
| K15 | Essential | **kp-themes and chrome from one place.** The kit vendors kp-themes v3.1.0 (checksum-gated in the kit's CI), serves the theme picker, no-flash snippet, skip link, `data-kp-confirm` / `data-kp-busy` behaviours; static assets embedded with `include_str!` and served with a content-hash `?v=` and a one-year immutable cache header. | CI gate: vendored files match the release's SHA256SUMS. E2E: `/static/<file>?v=<hash>` returns `Cache-Control: immutable`; a changed asset changes the hash. |
| K16 | Essential | **Layout with extension hooks and an explain block.** One minijinja layout with named blocks; a project registers nav entries, extra pages, status-page sections, and extra columns/actions on the client row; every section carries an explain block (short plain-language text above the table). | E2E: the example registers one page, one status section and one client column and all three render; a page without an explain block fails a template lint test. |
| K17 | Essential | **Status page and problems card.** Version, uptime, health per subsystem, the update card (current version, latest release, last check, mode, hold, rollback state), a problems card the project feeds (configuration that failed to load, with reason and a reload action), then project sections. | E2E: every field on the status page is shown to take two values in the suite (rule 22); the update card shows "off" and "supervised" in two runs. |
| K18 | Essential | **Self-update module, three modes.** `off` / `supervised` / `autonomous`, exactly one armed, container detection forces `off`. Supervised = `<name> update`: one attempt, fetch VERSION → SHA256SUMS + .minisig → binary, verify signature then hash, probe with `--check`, rename swap, exit 0 (also when already current), never restart, no state written. Autonomous = a timer (`<PREFIX>_UPDATE_INTERVAL_SECS`), same pipeline, self-restart, rollback marker restores the previous binary when the new one does not report healthy within `<PREFIX>_UPDATE_HEALTHY_AFTER_SECS` over `<PREFIX>_UPDATE_MAX_START_ATTEMPTS` starts; one log line per cycle at info (rule 23). Starting code: Almanac's `core/update.rs` + `shell/update.rs`. | Unit: version comparison, decision table (9 cases from Almanac). E2E with a local fake release server: supervised update swaps the file and exits 0; second run exits 0 without touching the file (hash equal); autonomous rollback restores the previous binary after a probe failure. Paused-clock test for the first tick (Almanac lesson). |
| K19 | Essential | **Release layout and signing.** Every release: `<name>`, `SHA256SUMS`, `SHA256SUMS.minisig`, `VERSION`; CI builds and uploads the first two with `GITHUB_TOKEN`; `chassis release` (K23) signs locally with the one ecosystem minisign key; the public key is compiled into the kit and is the only trust anchor the updater uses. | Regression vector: one real signature made with Kenny's key over a fixed manifest (rule 9). Unit: a manifest with a wrong signature is refused before any hash is read. |
| K20 | Essential | **Hold, drill flag, version check when off.** `<PREFIX>_UPDATE_HOLD=<version>` pins or skips; `<PREFIX>_UPDATE_DRILL=broken` makes the updater install a release that verifies but exits non-zero on start (for the homelab's broken-release drill); in mode `off` the kit still fetches VERSION and shows it on the update card. | E2E: hold prevents a swap that would otherwise happen; drill installs a marked-broken binary and the rollback path (K18) recovers; in `off` the card shows a newer version without swapping. |
| K21 | Essential | **State copy before a swap, one-version-back migrations.** Before any binary swap the kit asks the project for a consistent copy of its state (hook; kyu's `VACUUM INTO` is the reference) into `<state>/pre-update/<version>/`, pruned to `<PREFIX>_UPDATE_KEEP_COPIES`; the kit's own store format carries a version and stays readable by the previous minor version; the scaffold ships a test template asserting that. | E2E: a swap leaves a copy; a store written by version N opens in a build of N-1 (test in the kit for its own store). |
| K22 | Essential | **Notifier as per-event webhooks.** Fixed kit events (`update.ok`, `update.failed`, `update.rolled_back`, `health.degraded`, `service.started`) plus project events; per event zero or more webhooks (URL, method, headers, body template with event fields; secrets from env via `${VAR}`); presets `kyu-topic` and `ha-webhook`; optional fallback chain; delivery never blocks the caller. | E2E with a local receiver: event → one POST with rendered body; primary down → fallback receives; a header value from `${VAR}` never appears in logs. |
| K23 | Essential | **The `chassis` scaffold command.** `new <name>` writes Cargo.toml, main.rs, CI + release workflows, Dockerfile, systemd unit (golden), `service.yml`, sign script, `.githooks`, `deny.toml`, `rust-toolchain.toml`, README skeleton, and creates + configures the GitHub repo via `gh` (public, branch protection with required checks once CI has run); `sync` shows per-file diffs against the current scaffold; `release <version>` bumps, tags, waits for the tag's CI run, downloads the artefacts, verifies checksums, signs locally, uploads `.minisig` + `VERSION`, and prints what it did. | E2E: `new` in a temp dir produces a project that passes `cargo build` and its own gates; `sync` reports zero diffs right after `new` and one diff after a template change; `release` is drilled against a scratch repo (rule 14) with a dry-run flag for CI. |
| K24 | Essential | **Readable for a beginner.** `examples/minimal.rs` (one file, ≤40 lines), rustdoc opening every module in plain English, a concrete API (no generic builders), an `ARCHITECTURE.md` with the eject route (which module to copy for what). C4 in SCOPE.md is the acceptance test. | Doc test: every public module has a doc comment starting with a sentence, checked by a lint test; the minimal example compiles as a doc/example target in CI. |
| K25 | Essential | **Test helpers, semver, consumer builds.** `chassis::testing`: start an app in-process on port 0, a `Clock` trait with a paused implementation, a fake release server; semver over the Rust API and the scaffold file shapes with migration notes in CHANGELOG.md; the kit's CI builds the example and, once they exist, the migrated consumers against the release candidate. | The kit's own suite uses only the helpers; `cargo semver-checks` runs in CI (informational until 1.0); CHANGELOG lint: a major bump without a "Migration" heading fails. |

## Round 2 — Claude's proposals (W)

| ID | Rating | Feature | Test bar |
|---|---|---|---|
| W1 | Essential | **Request-id.** Every request gets `x-request-id` (accepted from the proxy if present, else generated), carried in every log line of that request and echoed in the response. | E2E: a supplied id is echoed; a missing one is generated; the access log line contains it. |
| W2 | Desired | **clap for the CLI, one backoff helper.** clap 4 derive for all commands and flags (unknown flags refused); a backoff-with-jitter helper (base, cap, jitter) used by the updater and offered to projects. | Unit: backoff sequence within bounds over 1000 samples; `--help` snapshot test. |
| W3 | Essential | **Distroless self-probe.** Folded into K7: `--healthcheck [url]`. | see K7 |
| W4 | Desired | **Quiesce and backup-paths contract.** `<name> quiesce --for <secs>` (or an admin endpoint) pauses writers and fsyncs; `<name> backup-paths` prints the directories the nightly must take; the homelab builds the caller once this exists. | E2E: during quiesce a write blocks and completes after; `backup-paths` lists exactly the state root's durable dirs, never caches. |
| W5 | Later | **Token scopes.** Per-client route allow-lists. Registered, no hook in the kit. | — |
| W6 | Don't do | **Unprotected mode with banner.** Kenny 2026-09-05: the kit never starts a dashboard without both secrets; kyu loses this behaviour when it migrates. | — |
| W7 | Don't do | **`/readyz`.** The homelab does not need it; `/healthz` carries subsystem status. | — |
| W8 | Don't do | **In-process TLS.** TLS is Traefik's job (C2 in the deep-dive round). | — |
| W9 | Essential (proposed during AFK, ratify in R2) | **systemd readiness notify.** The golden unit uses `Type=notify`; the kit sends `READY=1` after the socket is bound and the stores opened, so `systemctl is-active` — the only health signal the homelab's update supervision reads today — means "bound and serving", not "process exists". Falls back silently when `NOTIFY_SOCKET` is unset. | E2E on CT 118: `systemctl start` returns only after `/healthz` answers; a unit with `ExecStart` pointing at a binary that fails `--check` never reaches active. Unit test: no `NOTIFY_SOCKET` → no error. |

## Mandatory items (M)

| ID | Item | Answer |
|---|---|---|
| M1 | **Update & distribution** | Built-in, signed self-update with three modes (K18–K21); the kit itself is distributed as a git dependency pinned to a tag with SHA256SUMS beside the tag (N3 in SCOPE.md); the `chassis` binary is a release asset like any service. |
| M2 | **Ecosystem integration** | **kyu**: notifier preset `kyu-topic` (K22); no other coupling. **latch**: the golden unit supports `ExecStart=latch run --env prod -- <binary>` as an alternative to `EnvironmentFile`; the kit reads env only, never `.env`. **homelab**: `service.yml` from the scaffold, supervised update contract, `/healthz` version field, one state root — G4. **kp-themes**: vendored v3.1.0 in the kit (K15). **HTTPSwitchboard / kyu-runner / Almanac**: consumers-to-be, not dependencies. |
| M3 | **Backup & restore** | State = the encrypted client store, sessions and passkeys (one file each under `<state>/`), the project's own data, the config file if it lives under the root, and the pre-update copies (K21). Regime: the homelab's nightly tar of `data_dirs` (live today; quiesce via W4 later). **Restore drill:** on CT 118, before the 1.0 release: destroy the state, restore the tar, start, log in with an existing client token — queued as measurement in docs/PENDING_MINI_ROUNDS.md. |
| M4 | **Data & config location** | One root `<PREFIX>_STATE_DIR` (default `/var/lib/<name>`; the homelab's `service.yml` sets `/appdata/<stack>/<name>-config`); config file at `<root>/config.toml` unless `--config` says otherwise; secrets only via env / EnvironmentFile / `latch run`; caches (update staging) live **beside the binary**, not under the root, because the rename swap needs the same filesystem; logs go to stderr → journald. Written into ARCHITECTURE_DECISIONS.md as the configuration surface. |
